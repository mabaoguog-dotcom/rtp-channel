# RTP 助手频道推送

频道：@rtpbodon；机器人：@RTPZSBOT。

- 计划每5分钟检查老虎机大额派彩，GitHub排队可能造成延迟，不是秒级实时。
- 每个UTC小时的第一次实际运行发送一组RTP汇总，仅从中文名已核实的活跃游戏中按近24小时投注笔数选第1名，按同款游戏对照近10分钟、1小时、24小时。
- 大额门槛默认为单笔派彩至少10000美元，且派彩大于投注；每滚动小时最多6次发送尝试，同款至少间隔10分钟。
- 仅推送中文名已核实的游戏，点击中文名可看出处。未找到可靠中文名的游戏直接跳过，不在频道显示“中文名待核实”；不自动翻译。
- 不向频道发送异常、故障或数据状态通知；后台错误只写Actions日志。

## 控制任务

打开 Actions → Slot RTP channel。

- 手动预览：Run workflow，不勾“实际发送”。
- 手动发送：Run workflow，勾“实际发送”。
- 暂停自动推送：任务页面右上角三个点 → Disable workflow。
- 恢复：Enable workflow。

此版定时运行默认实际发送，不再依赖旧版ENABLE_PUSH变量。机器人Token继续保存在仓库Actions Secret `TELEGRAM_BOT_TOKEN`，不要写进代码。

## 去重与边界

`rtp-bot-state`分支仅保存去重与每小时处理状态，请勿删除。程序先写入远端占位再发送；发送结果未知时不会盲目重发，因此可能漏掉个别记录。长时间中断、源站抽样、限频和分页上限也可能造成遗漏。

大额消息展示事件时间和检查时间，且不展示玩家身份。历史RTP与派彩不能预测下一次结果。

数据与接口：https://gambatracker.com/developers

大额派彩采用对应游戏封面制作JPEG海报，并将派彩、倍数、投注额及事件时间作为图片说明一并发布；缺少封面时明确显示“游戏封面暂无”，不使用其他游戏图片。

用户私聊发送 `/start` 后，Webhook直接回复聊天键盘。GitHub只负责频道定时推送，不再取聊天消息。仅响应私聊指令，不在仓库存储聊天内容。

每小时第一名以一条图片帖子发送：第一名游戏的原始海报，10m/1h/24h等数据保留在原有文案里，图片不叠加数据。原始海报缺失时仅发原有文案。

聊天键盘：实时RTP、活跃第一名、最新大额派彩、搜索游戏、打开数据站、使用说明。用户重新发送 `/start` 显示键盘；周期按钮在聊天里回复观测数据。聊天由Webhook即时接收，数据查询需要读取公开接口；不再等待GitHub排队。

聊天和小程序共享经来源核实的中文名目录，支持部分名称、简繁体、空格/标点兼容。详见 CHINESE_NAMES_AUDIT.md。

Webhook部署在现有小程序站点的 `/bot/webhook`。回调通过Telegram secret_token校验。Bot Token继续仅保存在GitHub Secret中，配置任务直接调用Telegram设置回调。网站不接收、不保存Bot Token；实际回复使用Telegram Webhook响应方式。
